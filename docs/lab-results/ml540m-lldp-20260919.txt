RESULT

The 2026-09-18 conclusion -- "LLDP-based topology discovery cannot be assumed
for the switch" -- is NOT supported as stated.

- The standard LLDP-MIB IS implemented: configuration group and
  lldpLocalSystemData both respond with real data, and LLDP is running in
  txAndRx mode on all ten ports.
- Only the PROPRIETARY status subtree is missing. That part of the original
  finding stands.
- The neighbour table could not be evaluated either way, because all 30
  interfaces are operationally down. With no link up there is no neighbour to
  learn, so an empty lldpRemTable is the correct result, not a defect.

STILL TO DO: bring up one link to an LLDP-speaking device and re-walk
1.0.8802.1.1.2.1.4.1 (lldpRemTable). Until then the neighbour path is
untested rather than broken.

Useful side findings:
- lldpLocChassisId gives the switch's MAC and lldpLocSysName gives a real
  deployed device name ("XMJ1-XMJ2-M540-02-010") -- both better inventory
  keys than productModel, and both available over the standard MIB.
- lldpLocSysDesc carries the firmware version and build date, which is a
  cheap per-device firmware-drift signal.
- Standard IF-MIB is implemented on the switch, so interface counters are
  available for PM (see docs/mib-analysis/coverage-gaps.md, where IF-MIB was
  flagged as an uncovered gap).
